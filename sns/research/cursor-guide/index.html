Cursor & Git 活用ガイド

1. 概念の整理：Git と GitHub は別物

概念・システム

Git

「バージョンを管理する」仕組みそのもの。

🏠 例え：日記帳
昨日書いた内容を消さずに、新しいページに今日の分を書く「書き方」のルール。
サービス・場所

GitHub

ファイルを保存・共有する「場所」。

図書館（クラウド）
書いた日記帳を預けて、他の人も読めるようにしたり、バックアップをとっておく場所。
💡 正しい伝え方のコツ

「Gitを活用した」と言うと、エンジニアには「バージョン管理の仕組みそのものを使った」と聞こえます。
「GitHubに同期（保存）しました」と伝えるのが、最もスムーズで誤解のない表現です。

2. Cursor 最強の開発フロー

「自分で調べてから聞く」のは古い。最初からAIにオープンに投げるのが正解。

🚀 なぜ Gemini(Web版) ではなく Cursor なのか？

Web版でのコピペ作業は、「情報の断絶」を生みます。Cursorなら、プロジェクト全体のファイルをAIが把握しているため、 「あのファイルとこのファイルを組み合わせて、新しいツールを作って」という指示が、コンテキスト（文脈）を維持したまま一瞬で完了します。

1
ASK モード 思考の壁打ち・超高度検索
🧠 なぜ最初が ASK なのか？
AIは「あなたの思考過程」を読み取るのが得意です。最初から完璧な指示（プロンプト）を作ろうとせず、 「こんな感じにしたいけど、どう思う？」というラフな相談から始めることで、AIがあなたの意図を深く理解し、より精度の高い提案を引き出せます。
💡 ASK でできること：
  • 音声入力で雑談相談： 手を動かさず、頭の中をそのまま言語化。
  • 「わからないこと」を聞く： 用語の意味や、次に何をすべきか。
  • 参考URLの要約： 「このサイトみたいなUIにするには？」と聞く。
  • プロジェクト内検索： 「あの時作ったコードどこだっけ？」

3. 「AIがバカになる」を防ぐ：コンテキスト管理

AIは、会話が長くなると急激に精度が落ちます。

☕ 例え：コーヒーカップの容量

会話（トークン）を注ぎ続けると、カップが溢れて古い記憶からこぼれ落ちます。 溢れた状態のAIは、さっき言ったことも忘れる「ボケた状態」になります。

0% (最強) 50% (注意) 100% (使い物にならない)
💡 解決策：新しいカップに注ぎ直す
ASKで話しすぎてゲージが溜まったら、PLANを書き出させてから「New Chat」。 重要なエッセンスだけを新しいチャットに持ち越すことで、知能をフルパワーに戻せます。

4. 報告の極意：前提を伝える

「何を作ったか」の前に「なぜそれをしているか」を一行入れるだけで評価が変わる。

  • ❌ 「図解作りました。見てください。」
  • ✅ 「操作に慣れる練習として、まずは図解ツールを作成してみました。共有します。」
